## 2. 安全/数据评审

范围：输出路径、输入只读、重复规则资源消耗、demo 覆盖、权限。评审报告 1 个高危、2 个中危、1 个低危、1 个文档问题。

| 编号 | 发现 | 复现 | 处理 |
|---|---|---|---|
| SEC-1（高） | `--force` 可把 `--html/--json/--plan-out` 写到输入 `.ics` 上，输入被 HTML 覆盖 | `audit input.ics --html input.ics --force`，退出 0、输入哈希变化 | 写前 `reject_input_collisions`：`os.path.samefile`、解析路径、同目录大小写；退出 2，输入哈希不变。测试 `test_output_cannot_overwrite_input`、`test_plan_output_cannot_overwrite_input` |
| SEC-2（中） | 事件上限在 `between()` 全量展开后才检查；极小 SECONDLY 规则可耗数 GB | 250 字节 `RRULE:FREQ=SECONDLY` → 20.6s、2.28GB RSS，后退出 4 | 展开前按 FREQ/COUNT/INTERVAL/窗口估算；SECONDLY/MINUTELY 无 COUNT 拒绝，COUNT 受限放行。测试 `test_secondly_recurrence_is_rejected_before_expansion`、`test_hourly_recurrence_budget_rejects_before_expansion` |
| SEC-3（中） | `demo --force` 可覆盖真实 `work.ics`，且坏配置可能在写文件后才报错 | 目录放真实 `work.ics` + `--force`；或坏 `WEEKGLASS_TZ` | 先校验配置；demo 只允许示例文件名，示例日历内容不符即退出 6；测试 `test_demo_refuses_to_overwrite_real_calendar`、`test_demo_invalid_config_does_not_touch_files` |
| SEC-4（低） | 大小写不同的输出路径可绕过重复检测；硬链接同理 | `Report.json` vs `report.json`；硬链接 | `_same_path` 用 `samefile` + 同目录 casefold；测试 `test_duplicate_outputs_via_hard_link_are_rejected`，手工复现大小写版本退出 2 |
| SEC-5（文档） | shell `>` 重定向生成 0644，与“输出 0600”承诺不一致 | `weekglass audit --json - > report.json` | README 已知限制和 D-41 写明区别；CLI 直接写仍 0600 |

复现说明：大小写碰撞第一次手工复现时，`input.ics` 已被前一条高危用例覆盖，得到的是 `invalid_ics` 而不是碰撞；换干净输入后确认退出 2、目录无输出。这是复现步骤问题，不是产品误报。
