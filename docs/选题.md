# 选题：Weekglass（周镜）

调研日期：2026-10-29。证据只取公开可访问的页面；链接旁的说明是该页面实际表达的内容，不是推测。
评价口径：先看“谁在痛”，再看“我能不能每周用、30 秒内演示、第一版做透”，最后才看热度。

## 一句话结论

做 **Weekglass（周镜）**：本地优先的日历碎片审计与专注计划 CLI。用户把一个或多个 `.ics` 日历交给它，它用一条命令回答三个问题：这一周有多少时间被占用、空闲被切成了多少段、下周可以把哪几块完整时间放回日历。它不连网、不要 OAuth、不自动移动会议，只读日历、只写一个可导入的 `focus.ics`。

---

## 1. 八个候选

### 候选 1：Weekglass — 日历碎片审计与专注计划

- **具体人群**：每周有 6 个以上会议、同时用工作与个人两个日历的 22–35 岁知识工作者或研究生；他会在周日晚上想“下周哪几天能安静写东西”，但只能靠翻日历目测。
- **现在怎么解决**：Google/Outlook 日历里手动拉“专注时间”块；用 Reclaim.ai、Clockwise 之类云端工具自动挪会议；或者干脆不解决，接受每天被切成四五段。
- **痛在哪里**：会议之间的 30–60 分钟既不够进入状态，又容易被继续切碎；一周结束后说不清时间去了哪里；自动排程工具会移动别人的会议，且要把完整日历授权给云端。
- **核心流程哪里明显更好**：`.ics` 原生、多日历合并去重、把“碎片率/最长连续空闲/完整专注块”算成可复现的数字，并直接生成可导入的专注块。全程本地，不需要账号。

4. Hacker News《Ask HN: Meeting overload – how many do you have daily/weekly?》：专门询问会议过载的讨论帖。https://news.ycombinator.com/item?id=22526645

**为什么现在做**：Clockwise 已宣布 2026-03-27 停止服务（官方公告：https://www.getclockwise.com/pricing ），Reclaim.ai 被 Dropbox 收购；云端自动排程的替代品在收缩，而“本地、可审计、可导出”的需求没有被满足。

### 候选 2：HoldLens — ETF/基金穿透与重叠分析

- **具体人群**：持有 5–15 只 ETF、分布在 2–3 个账户的 DIY 指数投资者；他以为 VOO + VTI + QQQ 很分散，但说不清前十大持仓重复了多少。
- **现在怎么解决**：Morningstar X-Ray（付费/顾问版）、etfrc 之类的网页两两对比、Portfolio Visualizer、自己维护 Excel。
- **痛在哪里**：组合层面的真实暴露、基金重叠、加权费率、单一股票集中度都要手工拼；网页工具按基金对对比，不给“整个组合”的答案；数据滞后且不可复现。
- **核心流程哪里明显更好**：一次导入持仓，输出“穿透后的股票/行业暴露 + 两两重叠 + 组合加权费率 + 前十大真实持仓”，本地可复跑。

### 候选 3：HoldLine — 投资论点与卖出纪律

- **具体人群**：持有 10–30 只个股/基金、会写投资笔记但从不回看的个人投资者；他买的时候有理由，跌 20% 后只记得成本价。

- **痛在哪里**：买入理由、关键假设、什么情况下卖出没有和持仓绑在一起；每周/每季度没有固定回看动作；最后只剩下盈亏数字驱动决策。
- **核心流程哪里明显更好**：每个持仓强制写“论点 / 关键假设 / 失效条件 / 下次复核日”，每周生成只包含“到期复核 + 论点变化”的清单；不预测价格，不推荐买卖。

### 候选 4：Driftline — 组合再平衡与交易清单

- **具体人群**：有 3 个账户、6–12 只基金、每季度想再平衡但每次都被“先卖哪个账户、先买多少”卡住的指数投资者。
- **现在怎么解决**：Bogleheads 风格的 Excel 再平衡表、Portfolio Performance 桌面软件、Passiv（付费、连接券商）。
- **痛在哪里**：多账户让目标权重和实际权重对不上；有新增现金时不知道该先补哪个；卖出涉及税优/应税账户顺序；表格公式一改就坏。
- **核心流程哪里明显更好**：CSV 导入持仓与目标权重，按“先用现金、再在税优账户卖、最后才动应税账户”的顺序生成最小交易清单，并给出再平衡前后的偏离。

### 候选 5：DataReel — 数据到竖屏视频

- **具体人群**：每周要把 CSV/图表做成 30–60 秒竖屏视频的分析师、记者或知识博主。

### 候选 6：CaptionFix — 字幕时间轴修复

## 2. 进入决赛的四个候选：竞品没做好的三件事

> 说明：Reclaim、Clockwise、Morningstar X-Ray、Passiv 是闭源产品，没有公开 issue 列表；这里读的是官方文档/定价/停服公告，以及 Hacker News 上可核对的用户反馈。Portfolio Performance、Ghostfolio 是开源项目，读了公开 issue 列表。

### Weekglass vs Reclaim.ai、Clockwise

**Reclaim.ai**（https://reclaim.ai/pricing）

1. 需要 Google/Microsoft OAuth，把完整日历授权给云端；本地文件和离线场景没有入口。
2. 核心是自动排程/自动移动，用户很难只要“审计 + 建议”，而不让工具改日历。
3. 没有可复现的本地报告，也没有把多个导出的 `.ics` 合并去重的路径；离开订阅就带不走分析结果。

**Clockwise**（https://www.getclockwise.com/pricing）

1. 官方已宣布 2026-03-27 停止服务；依赖它的团队需要迁移。
2. 同样是云端 + 工作账号，个人日历/混合日历支持有限。
3. 价值集中在“挪会议”，不回答“这一周碎片率多少、最长连续空闲多少”，也没有可分享的静态审计报告。

### HoldLens vs Morningstar X-Ray、ETF Overlap Tool/etfrc

**Morningstar X-Ray**

1. 组合穿透是付费/顾问产品的一部分，个人用户门槛高。
2. 报告以网页为主，不能把同一份持仓在本地反复跑、做版本对比。
3. 数据与分类口径不透明，用户无法核对“为什么这只股票被算进这个行业”。

**ETF Overlap Tool / etfrc**

1. 以两只基金的两两对比为主，不给整个组合的穿透暴露。
2. 不合并账户，也不计算组合加权费率。
3. 纯网页、不可脚本化，无法进入每周/每季度的固定流程。

### Driftline vs Portfolio Performance、Passiv

**Portfolio Performance**（开源，https://github.com/portfolio-performance/portfolio）

1. 桌面 GUI 功能全，但学习曲线陡；再平衡 issue 仍在讨论“通过新增资金再平衡”等基础流程（#1238、#5971）。
2. 不给“先现金、再税优账户、最后应税账户”的默认交易顺序。
3. 没有 CLI/静态报告，难放进脚本或每周固定流程。

**Passiv**（https://passiv.com/pricing）

1. 付费（Elite $99/年），且依赖券商连接；没有券商 API 的市场用不了。
2. 以北美券商生态为中心，税优账户模型不通用。
3. 不能只拿一份 CSV 在本地跑，也不给可审计的计算过程。

### HoldLine vs Ghostfolio、Portfolio Performance

**Ghostfolio**（https://github.com/ghostfolio/ghostfolio）

1. 强在持仓跟踪和收益统计，不强制记录“买入论点/失效条件”。
2. 没有“本周到期复核”这类纪律流程，仍要用户自己记得回看。
3. 自托管需要数据库和长期维护，对只想写投资笔记的人过重。

**Portfolio Performance**

1. 强在绩效计算，不管理论点和卖出纪律。
2. 桌面软件，笔记与持仓的关联弱。
3. 没有面向“每周 10 分钟复盘”的轻量输出。

## 4. 为什么选 Weekglass

1. **每周真的会用**：周日晚上或周一早上跑一次，决定下周把哪几块时间保护起来；不需要等季度再平衡，也不需要先整理持仓 CSV。
2. **30 秒能演示**：`weekglass demo` 在空目录生成示例日历、报告和 `focus.ics`；一条命令后打开报告就能看到“10 小时 30 分完整专注、55% 碎片率、三个建议”。
3. **第一版能收口**：只做 `.ics` 读取、指标、建议、导出，不碰 OAuth、不碰自动改日历、不碰团队排期；每个数字都能用测试复现。
4. **竞品在收缩**：Clockwise 停服、Reclaim 被收购，云端自动排程的信任成本上升；“本地 + 可导出 + 可审计”是清楚的差异。
5. **风险可控**：没有外部服务、没有密钥、没有模型编造；最大的风险是时区/重复事件算错和报告泄露隐私，这两类都能用测试和默认行为防住。

## 5. 适用 / 不适用

**适用于：**

- 用 Google Calendar、Outlook 或 Apple 日历，能导出或订阅 `.ics` 的知识工作者、研究生、独立开发者；
- 每周有 5 个以上会议，想把会议集中、给深度工作留出完整块的人；
- 在意隐私，不想把日历授权给云端 SaaS，或需要把分析结果留档/分享给同事的人。

**不适用于：**

- 需要自动移动会议、团队排期、预约链接的人：应该用日历自带的预约页或 Reclaim/Clockwise 类工具；
- 需要任务管理、时间追踪、番茄钟、习惯打卡的人：Weekglass 只读日历，不管理任务；
- 只用一个日历、几乎没有会议，或不愿意导出 `.ics` 的人：手写时间块更快。

## 6. 明确不做（第一版非目标）

- 不做 Google/Microsoft OAuth，不直接调用日历 API，不自动修改用户日历。
- 不做团队排期、会议室预订、预约链接。
- 不做任务清单、时间追踪、应用使用统计。
- 不做账号、云同步、多人协作、服务端。
- 不做 LLM/自然语言问答；所有指标都是确定性计算。
- 不发布到 PyPI/npm；安装方式是从仓库本地安装，发布由维护者决定。
